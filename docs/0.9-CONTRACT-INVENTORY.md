# Omen 0.9-A Contract Inventory

This evidence-based inventory records the contract exposed by accepted Omen 0.8. It is an audit, not a runtime redesign. No executable semantics, schemas, status names, persistence schema, or MCP result shapes were changed.

## 2. Public CLI surface

Actual `target/debug/omen.exe --help` exposes `orient`, `capabilities [GROUP]`, `doctor`, `describe [CAPABILITY]`, `how RECIPE`, `context`, `tool`, `fact get/why`, `exec`, `artifact read/inspect`, `gc`, `daemon`, `mcp`, and `action list/show/plan/run`. Global machine-facing options are `--json`, `--machine`, and `--workspace`; `--version` exposes build identity. `exec` adds bounded timeout/output controls; `action run` requires `--expect-plan` and supports per-step execution-contract bindings.

The requested `omen history` command does not exist in the actual CLI. History exists through `omen_history_query`, daemon, and interactive surfaces. This is a discoverability inconsistency.

## 3. Public MCP surface

The actual `tools/list` set is: `omen_orient`, `omen_capabilities`, `omen_describe`, `omen_recipe`, `omen_context`, `omen_action_list`, `omen_action_show`, `omen_action_plan`, `omen_workspace_status`, `omen_facts_query`, `omen_execute`, `omen_execution_status`, `omen_history_query`, `omen_services_list`, `omen_services_control`, `omen_capabilities_discover`, `omen_symbol_search`, `omen_symbol_definition`, `omen_symbol_references`, `omen_structure_search`, and `omen_package_query`.

Required input fields are: `capability_id` for `omen_describe`; `recipe_id` for `omen_recipe`; `action_id` for action show/plan; `argv` for `omen_execute`; `request_id` for execution status; `query` for symbol search; `symbol` for definition/references; and `pattern` for structure search. Other fields are optional filters, limits, workspace context, or no-input calls as declared in `crates/omen-mcp/src/server.rs`.

CLI and MCP use the same Machine Contract definitions, but CLI prints JSON directly while MCP wraps JSON text in JSON-RPC `result.content[].text`; MCP errors are currently prose content with `is_error`.

## 4. Status vocabulary

| Concept | Internal type | Canonical spelling |
|---|---|---|
| Physical runtime | `RuntimeStatus` | `COMPLETED`, `SPAWN_FAILED`, `TIMED_OUT`, `CANCELLED`, `CONTAINMENT_FAILED`, `IO_FAILED` |
| Adapter outcome | `AdapterClassification` | `SUCCESS`, `FAILURE`, `REFUSAL`, `UNKNOWN` |
| Action report | `ActionRunStatus` | `COMPLETED`, `FAILED`, `REFUSED`, `TIMED_OUT`, `PARTIAL` |
| Action step | `ActionStepRunStatus` | `COMPLETED`, `FAILED`, `REFUSED`, `TIMED_OUT` |
| Consequence truth | `StateChange` | `NO`, `YES`, `POSSIBLE` |
| Availability | `AvailabilityState` | `available`, `unavailable`, `unknown` |
| Admission projection | `AdmissionState` | `admitted`, `not_admitted`, `unknown` |

Other canonical enums are `ValidityState` (`CURRENT`, `DIRTY`, `STALE`, `SUPERSEDED`, `HISTORICAL`), `Assurance` (`DETERMINISTIC`, `VERIFIED`, `ENFORCED`, `OBSERVED`, `CLAIMED`, `INFERRED`, `UNKNOWN`), `EnforcementLevel` (`ENFORCED`, `MEDIATED`, `OBSERVED`, `BEST_EFFORT`, `UNSUPPORTED`), `BlobState` (`PRESENT`, `EVICTED`, `MISSING`), retention, PTY, and runtime-lease states.

Semantic lookup uses `resolved`, `ambiguous`, `stale`, `not_found`, and `unsupported`. Provider failure is an outer `Result::Err(CoreError)`, not `not_found`. `PREVENTED` is accepted as an input alias for canonical `ENFORCED`.

## 5. Error vocabulary

`crates/omen-core/src/error.rs` defines `INVALID_URI`, `INVALID_ID`, `SCHEMA_VIOLATION`, `UNSUPPORTED_SCHEMA_VERSION`, `NOT_FOUND`, `FACT_DIRTY`, `FACT_STALE`, `ASSURANCE_NOT_SATISFIED`, `EXECUTION_FAILED`, `SPAWN_FAILED`, `TIMED_OUT`, `CANCELLED`, `CONTAINMENT_FAILED`, `IO_FAILED`, `REFUSAL`, and `INTERNAL`.

`CoreError` does not have distinct variants for every `ErrorCode`; several physical conditions are carried as `ExecutionFailed` or surface-specific strings. The planner separately emits configuration, identifier, reference, type, capability, runtime, and action errors such as `OMEN_CONFIG_VERSION_UNSUPPORTED`, `OMEN_CONFIG_BOUNDS`, `INVALID_ACTION_ID`, `DUPLICATE_STEP_ID`, `UNKNOWN_CAPABILITY`, `TYPE_MISMATCH`, and `ACTION_NOT_FOUND`.

Composition adds authority, capability, schema, evidence, network, nesting, bounds, step, timeout, and workspace-scope strings including `AUTHORITY_REQUIRED`, `AUTHORITY_CONTRACT_INVALID`, `AUTHORITY_CONTRACT_MISMATCH`, `CAPABILITY_UNAVAILABLE`, `EVIDENCE_SERIALIZATION_FAILED`, `TIMEOUT`, and `WORKSPACE_SCOPE_VIOLATION`. CLI/MCP add `PLAN_CHANGED`, `DELTA_UNAVAILABLE`, `EXECUTION_STATE_UNAVAILABLE`, `UNJOURNALED_LOCAL_EXECUTION`, `CAPABILITY_NOT_FOUND`, `RECIPE_NOT_FOUND`, `OMEN_CONFIG_INVALID`, `OMEN_CONFIG_TOO_LARGE`, and `OMEN_CONFIG_PATH_ESCAPE`.

Retryability is not consistently encoded. MCP errors are prose-only. This is a high-confidence contract risk, not a repair made by this audit.

## 6. Identity model

| Identity | Representation and creator | Stability/evidence |
|---|---|---|
| Workspace | `ws_` plus first 16 SHA-256 hex characters of canonical path with `/` separators | stable for canonical location; not content-based |
| Interactive session | `sess-<UUID v4>` | runtime-created; unique, not restart-stable |
| Execution | normally `exec_<UUID v4>` in daemon history; contracts may supply an ID | server-owned normally; caller-supplied in contract path |
| Consequential request | request/receipt string, commonly `req_<UUID>` or caller idempotency key | deduplication/status identity |
| Action | validated Omen.toml map key / `ActionId` string | configuration identity |
| Plan | `sha256:` digest of canonical planned structure | content identity of plan snapshot |
| Machine Contract | `sha256:` digest of canonical serialized contract | deterministic contract snapshot |
| Fact | `fact-` hash prefix over resource, value, and creation time | durable record identity; not content-addressed |
| Artifact | `artifact://sha256/<64 hex>` | content-addressed, stable for identical bytes |
| Resource | logical `ResourceUri` string | logical/location identity |
| Symbol | provider/index-derived `SymbolId` | provider-dependent and generation-sensitive |
| Provider | `SemanticProviderId` such as `rust-analyzer` or `scip` | adapter identity, not authority |
| Evidence | artifact URI and/or durable history/envelope | durable when captured; absence is reportable |
| Git state | repository refs/SHAs and observed facts | external state observed by adapters |

Generic IDs reject empty/control-containing strings but do not enforce their documented-looking prefixes. `ResourceUri` rejects traversal and backslashes but does not resolve filesystem aliases or junctions.

## 7. Evidence model

The authoritative path is:

```text
request -> request/receipt -> daemon broker -> execution id
  -> supervisor process result and enforcement report
  -> bounded inline output and optional CAS artifacts
  -> SQLite history, receipt, resource and artifact links
  -> machine response and later status/history/artifact retrieval
```

`ExecutionResult` is authoritative for runtime status, process exit, adapter classification, enforcement, observations, fact updates, artifacts, and reduced summary. Durable `ExecutionRecord` is authoritative for execution/session id, command, exit code, duration, artifact links, envelope, and creation time. CAS metadata and bytes are authoritative for captured output.

`ActionRunReport` is authoritative for multi-step status, completed count, failed step, per-step status, process exit, enforcement, artifacts, and conservative `StateChange`. Timeout may be `POSSIBLE`; refusal before execution is `NO`. Missing/evicted CAS means referenced bytes are unavailable, not that they never existed. Direct local execution can be marked `UNJOURNALED_LOCAL_EXECUTION`, distinguishing “not in durable daemon history” from “nothing ran.”

## 8. Resource and reference model

Accepted logical schemes are `workspace`, `tool`, `fact`, `observation`, `inference`, `artifact`, `proc`, `secret`, `net`, `actor`, `trace`, `symbol`, and `package`. The parser requires `://`, rejects unknown schemes, backslashes, control characters, and `..` segments, and requires `artifact://sha256/<64 hex>` for CAS references. It preserves the trimmed string and does not universally normalize case, filesystem aliases, junctions, or `C:\...` versus `file:///C:/...` versus `workspace://...`.

Semantic file paths are workspace-relative; ranges are zero-indexed internally and one-indexed for human display. LSP UTF-16 columns are converted at the adapter boundary. Windows physical paths remain filesystem inputs, not logical URI identities.

## 9. Omen.toml

Authoritative types are in `crates/omen-core/src/composition.rs`:

- `schema_version` must be `1`; top-level fields are `project` and `actions`;
- actions contain descriptions and ordered steps; steps contain ids, capability ids, and literal/prior-step-output bindings;
- `deny_unknown_fields` is active;
- bounds are 128 actions, 64 steps/action, 64 bindings/step, and 16 KiB strings;
- invalid names, duplicate/self/forward/missing references, and input/output type mismatches are rejected;
- planning validates and digests but does not probe, spawn, mutate, retry, or ask a model.

Omen.toml is strict and inert configuration, not a workflow programming language. It has no loops, conditionals, retry language, AI instructions, nested orchestration, rollback language, or permission invention. Authority remains in current external contracts/Tethers admission.

## 10. Authority boundaries

| Owner | Omen boundary |
|---|---|
| Omen | physical execution, containment, resources, observations, Facts, CAS, evidence |
| Tethers | policy, permissions, approvals, durable intent, outcome authority |
| Lantern | memory and provenance |
| Resolve | live coordination |
| ThreadMoth | bounded structural mutation |

Machine Contract entries mark consequential capabilities with authority text such as `Tethers admission`; `omen_recipe` explicitly grants no authority. Semantic providers report candidate/observational truth and are not permission calculators. Composition validates supplied contracts and plan identity; it does not manufacture authority.

Risk: `CapabilityStatus.admission` can look like a permission decision even though it is a runtime projection, and `authority`/`admission` occur in Omen plan/result types. Documentation must keep ownership explicit. No Omen-owned Tethers grant/approval DTO was found.

## 11. Agent discovery contract

The intended progressive path is `orient` -> `capabilities [group]` -> `describe` -> `how` when useful -> `context` -> action list/show/plan -> execute or action run only with the required current contract/plan identity.

`orient` teaches product/contract identity, digest, groups, recipes, references, context generation, and next calls. `capabilities` loads definitions and runtime overlay; `group` narrows it. `describe` is narrow; `how` is advisory and non-authorizing; `context` supplies live status or explicit unavailable delta. Execution requires explicit argv or a fresh deterministic plan and current external authority where applicable.

Baseline: one orient call is followed by about 19.7 KiB for the full capability catalogue or 1.85 KiB for a narrow describe. The path is deterministic and honest about unknown/unavailable state. Later work should measure calls, bytes, repetition, and caching rather than optimize blindly.

## 12. Cross-surface consistency and duplication

| Area | Current relationship | Finding |
|---|---|---|
| Discovery | CLI and MCP project `MachineContract`/`MachineContext` | semantically aligned; transport wrappers differ |
| Execution | CLI `exec`, MCP `omen_execute`, schema wire types, daemon IPC | same physical boundary; multiple envelopes/status layers |
| Actions | CLI/MCP list/show/plan; CLI run | plan identity aligned; MCP execution surface less complete |
| History | daemon/MCP expose history; CLI does not | public discoverability gap |
| Semantic lookup | core enum, direct MCP JSON, composition `{status,results}` | related truth, multiple serializers |
| Errors | `ErrorCode`, `CoreError`, planner/adapter strings, MCP prose | dangerous drift risk |
| Facts | typed records, SQLite uppercase states, CLI/MCP projections | broadly aligned; persistence is string-backed |
| CAS | typed URI, metadata `BlobState`, artifact access | strongest identity consistency |

Benign duplication includes schema wire structs, MCP transport metadata, and SQLite string persistence. Dangerous duplication is the error registry, prose-only MCP errors, semantic result envelopes, history asymmetry, and multiple ownership paths for execution IDs.

## 13. Candidate freeze decisions

### Freeze now

- Physical consequence truth: action/runtime statuses, `StateChange`, process exit, and enforcement.
- CAS URI form and SHA-256 content identity.
- Strict Omen.toml schema, planning bounds, and no authority/orchestration language.
- Machine Contract digest/version and static-contract/runtime-context separation.
- Semantic distinction among resolved, ambiguous, stale, not found, unsupported, and provider failure.
- Omen/Tethers/Lantern/Resolve/ThreadMoth ownership boundaries.

### Near-frozen

- Capability definitions and recipes: stable in spirit, but envelopes/errors need review.
- Fact validity and assurance vocabulary: heavily used, but persistence projections need migration tests.
- Typed identities and generation witnesses: sound model, with caller-supplied execution IDs and path aliases needing clarification.

### Needs 0.9 repair

- One structured error contract across core, CLI, MCP, and composition.
- History discoverability and CLI/MCP symmetry.
- One documented semantic result envelope or explicit versioned distinction.
- Explicit retryability, possible-state-change, and evidence-presence fields for machine errors.
- Windows path/URI alias comparison and artifact hash case rules.

### Internal / not contract

Provider lifecycle/readiness mechanisms, adapter process details, backend structs, SQLite query/layout details, provider-specific symbol ID construction, terminal styling, and preview-conveyor diagnostics.

### Remove before 1.0

No removal is justified by this audit alone. Obsolete aliases or dead compatibility paths need a separate evidence-backed cleanup decision.

## 14. Contract changes worth making before 1.0

Keep this budget deliberately small.

### 1. Add one structured public error envelope

- Problem: typed `ErrorCode`, `CoreError`, planner codes, adapter codes, and MCP prose can disagree.
- Evidence: `crates/omen-core/src/error.rs`, `composition.rs`, `composition_executor.rs`, CLI/MCP branches.
- Correction: define an additive, versioned machine error object with code, message, retryability, state-change classification, evidence references, and next actions; keep human prose as a projection.
- Compatibility/impact: additive JSON/MCP change; agents classify without scraping prose while human remediation remains concise.
- Why 0.9: contract freeze is the last low-cost point before 1.0 consumers depend on drift.

### 2. Make history discoverable consistently

- Problem: MCP has `omen_history_query`, but the actual CLI has no `history` command.
- Evidence: runtime `omen --help` and `crates/omen-mcp/src/server.rs`.
- Correction: add a documented CLI projection or explicitly declare history MCP/interactive-only and update discovery/docs.
- Compatibility/impact: additive command or documentation-only narrowing; improves human and agent discoverability.
- Why 0.9: this is a bounded product contract issue, not architecture.

### 3. Canonicalize semantic result projection

- Problem: direct MCP semantic results and composition semantic outputs use related but different shapes.
- Evidence: `SemanticLookupResult` versus `semantic_output` in `crates/omen-adapters/src/composition_executor.rs`.
- Correction: choose one versioned envelope or document the two projections as explicit transport contracts with shared status semantics.
- Compatibility/impact: likely additive/versioned; do not silently change accepted Preview 8 consumers.
- Why 0.9: semantic truth is central after the Preview 8 unsupported-coverage repair.

## 16. Verdict

The architecture is clean enough to freeze in principle, but the public contract is not yet clean enough to call fully frozen. The highest-value remaining work is a small error-envelope and cross-surface consistency repair, followed by the history discoverability decision. These are bounded stabilisation changes, not reasons to reopen 0.8 architecture.

**0.9-A VERDICT: REPAIRS REQUIRED.**

The 0.9-A.1 repair establishes `omen-core::OmenError` as the authority for
domain-error meaning. The registry and envelope are documented in
`docs/MACHINE-ERRORS.md`. Composition keeps its legacy `code`/`message`
projection for compatibility but serializes the canonical `error` envelope;
CLI machine failures and MCP tool failures use the same envelope. JSON-RPC
protocol errors remain separate by design. Further work is still required for
complete migration of every legacy producer and for the history discoverability
decision.
