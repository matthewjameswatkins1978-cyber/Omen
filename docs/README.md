# Omen Documentation

Omen documentation has three layers.

## The Omen Book

Start here if you want to understand Omen rather than merely look up a flag.

The Book explains why shells exist, why they survived graphical computing, why Omen keeps the shell instead of replacing it with chat, the AI-first and Harness Tax ideas behind the runtime, the Omen mental model, and how humans and agents share one machine reality.

Open:

docs/book/README.md

## The Omen Reference

Use the Reference when you already know what you are trying to do and need the exact surface.

Open:

docs/reference/README.md

The long-term goal is for command, capability, error and schema reference material to be generated or checked against Omen's canonical Machine Contract so documentation cannot quietly become a second source of truth.

## Documentation status

The accepted product baseline is Omen 0.7 Semantic Environment.

Omen 0.8 Composition & Discoverability is accepted for its documented
discoverability and composition boundaries. ThreadMoth composition execution
remains explicitly deferred pending a suitable current Tethers host seam.

Documentation rule:

> Explain the idea first. Show the shortest useful path next. Put exhaustive detail in the Reference.
