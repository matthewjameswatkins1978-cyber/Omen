# 14. Omen for humans

Omen is not an API server with a decorative prompt.

It should be a good shell.

## Calm by default

The prompt should answer a small question:

> Where am I, and is anything important enough to interrupt me?

Omen avoids persistent dashboard noise.

## Ordinary commands remain first-class

Experts should not be slowed down because Omen exists.

If git status is exactly what you want, type it.

Omen's value is not proportional to how many colons appear on screen.

## Completion

Completion can use runtime/semantic state to make suggestions relevant.

Ranking is advisory.

Fuzzy matching must not become authority.

## Pretty output is a projection

Colours, hyperlinks, OSC blocks and glyphs are presentation.

The structured object underneath is canonical.

A limited terminal should degrade gracefully.

## AI is available, never compulsory

The question-mark lane should make Omen more accessible.

It must not make the shell dependent on an AI provider.

## Strong defaults

Omen prefers a finished-feeling default over endless configuration.

Extensions should add capabilities, not furniture.
