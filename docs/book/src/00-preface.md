# Preface: what kind of book this is

Omen is unusual enough that a command list is not a sufficient manual.

You can learn the syntax of Omen quickly. The more important job is learning what kind of information Omen considers trustworthy, what it deliberately refuses to guess, and when an ordinary command, a semantic operation, a typed reference or an AI judgement is the right tool.

This book therefore begins before Omen.

It begins with the shell.

The accepted product baseline for this edition is Omen 0.7 Semantic Environment. Omen 0.8 Composition & Discoverability is being built while this edition is written. Where a chapter discusses an 0.8 surface that has not yet been accepted, it says so.

## Two ways to use these docs

If you are learning Omen, read the Book.

If you already know the model and need the exact CLI, action, reference, error or configuration shape, use the Omen Reference.

That separation is intentional. A tutorial should not drown in every option. A reference should not make you read a philosophy chapter to discover a flag.

## One sentence to carry into the rest of the book

> Omen keeps the directness of a shell, but tries to make machine state explicit enough that humans and agents do not have to reconstruct reality from terminal debris.

## A note about the earlier Operator's Manual

Much of its best material survives here: Facts are not memories, dirty is not false, provenance comes before guessing, AI judgement is explicit, and terminal presentation is not canonical truth.

The Book widens the lens.

It is for the person typing commands, the agent calling machine surfaces, and the developer trying to understand why Omen exists at all.
